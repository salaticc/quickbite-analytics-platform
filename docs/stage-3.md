# Stage 3 · Synthetic data and batch ingestion

## Запуск

Python 3.14, Docker Compose V2, команды из корня репозитория.

```bash
python -m pip install -r requirements-stage3.txt
docker compose up -d --wait --wait-timeout 180
python -m quickbite generate --profile smoke --seed 42 --output .quickbite-data/smoke
python -m quickbite ingest --input .quickbite-data/smoke
python -m quickbite verify
```

Команда `generate` создаёт новую папку. Для повтора с теми же данными выполните `ingest` с существующей папкой и затем `verify`. Чтобы проверить байтовую воспроизводимость, сгенерируйте тот же профиль в другой папке и сравните `manifest.json`. В нём находятся параметры генерации, количество строк и SHA-256 каждого CSV. Сгенерированные файлы исключены из Git.

| Профиль | Пользователи | Рестораны | Курьеры | Заказы | События |
| --- | ---: | ---: | ---: | ---: | ---: |
| `smoke` | 60 | 8 | 12 | 96 | 720 |
| `small` | 5 000 | 40 | 350 | 25 000 | 160 000 |
| `full` | 150 000 | 240 | 2 500 | 500 000 | 3 000 000 |

Поля `users`, `restaurants`, `couriers`, `orders`, `events`, `start_date`, `days`, `intervention_day`, `seed`, `repeat_uplift` и `prep_reduction_minutes` можно переопределить JSON-файлом через `--config`. Число ресторанов должно быть чётным для попарного назначения DiD. Пароли, порты и имена баз берутся из того же `.env`, что и Compose. Можно переопределить хосты `POSTGRES_HOST` и `CLICKHOUSE_HOST`.

## Модель событий и экспериментов

День заказа определяется по Москве, деньги хранятся в копейках, timestamps записываются с UTC-смещением. Распределения учитывают обеденный и вечерний пики, повторную активность разных сегментов, несколько списаний, запоздалые возвраты и недоставленные заказы. Часть сессий заканчивается на промежуточном шаге. Для заданного бюджета событий часть заказов может остаться без телеметрии.

A/B назначается хешем ID пользователя после доставки первого оформленного заказа в волне, если этот заказ доставлен. Назначение записывается до симуляции повтора. В treatment вероятность попытки повторного заказа выше на 5,5 п.п. по умолчанию. Фактический результат также зависит от отмен и случайности. В DiD рестораны сопоставлены парами по городу и базовому времени готовки. Один ресторан каждой пары получает вмешательство с общей даты. У групп одинаковый механизм предтренда, а эффект и случайный шум моделируются при обработке заказа. Параметры находятся в манифесте, исходы рассчитываются отдельно.

## Какая версия доступна читателям

PostgreSQL владеет восемью транзакционными сущностями. Загрузчик применяет CSV одной транзакцией, читает согласованный снимок и пишет его в новую базу ClickHouse. В неё также попадают события Stage 2 и канонические события пакета. В обычной базе ClickHouse остаётся структура Stage 2 для smoke и шаблона таблиц. Активный снимок выбирается записью `public.quickbite_batch_state` в той же транзакции PostgreSQL. `python -m quickbite verify` возвращает имя активной аналитической базы, её количество строк и сверку денежных сумм. Для запросов закрепляйте это имя на время сеанса.

Пакет публикуется после сверки количества строк, ключей, ссылок и сумм списаний и возвратов. При ошибке до публикации PostgreSQL откатывает импорт, предыдущее имя остаётся активным. Повторный запуск с тем же манифестом и снимком не меняет указатель. Попытка с другим манифестом завершается ошибкой. Для другого профиля используйте новый Compose-проект и свободные порты, чтобы сохранить предыдущий набор. Служебные таблицы и базы создаёт роль загрузчика.

Ограничения MVP. Один загрузчик на базу PostgreSQL, полный перенос при каждом запуске, одна серия синтетических данных на проект. При изменении источника с тем же манифестом сохраняется предыдущая аналитическая база для уже начавших чтение. При аварийном завершении процесса возможна база без ссылки из PostgreSQL. Перед её удалением проверьте активный указатель и читателей. Для `full` потребуется дополнительный диск для CSV и двух копий снимка во время загрузки. CI выполняет `smoke`.

## Проверки

```bash
python -m pytest -q -m "not integration"
```

На свежем Compose-проекте, до ручного ingestion, запустите в Bash:

```bash
QUICKBITE_INTEGRATION=1 python -m pytest -q -s -m integration
```

В PowerShell установите `$env:QUICKBITE_INTEGRATION = '1'` отдельной командой. Интеграционный тест имитирует сбой после записи части таблиц, проверяет откат первого импорта и сохранение активной версии после успешной публикации. Он печатает объёмы и времена в строке `STAGE3_SMOKE`.
